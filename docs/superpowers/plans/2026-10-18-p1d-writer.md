# P1d.1 Writer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a locked, run project into manuscript-ready files without any model computing or
writing a number:
- a bookmarked `manuscript.docx` (Methods, Results, tables, KM and forest figures, references);
- a `supplement.docx` (route tables, sensitivity analyses, deviations, multiplicity, feasibility and
  the STROBE checklist scored green / amber / red);
- `analysis.R` (the exact code that ran), `renv.lock`, CSL-JSON / RIS references, `placeholders.json`
  and a SHA-256 manifest;
- `SAP_v1.docx` and the feasibility-report docx.

**Architecture:** One headless pipeline under `app/R/writer/`.
- **Document model.** `sr_doc_model(project, opts)` builds a pure list of blocks: headings,
  paragraph templates, tables and figure specs.
  - Every number and every data-derived label enters a template only as a locked placeholder
    (`{{E12}}`, `{{L3}}`). A placeholder is a row of a registry that names its source: an effects
    row, a fragment number, a family adjustment, the feasibility fragment, the lock or the library
    snapshot.
  - Route fragments are P1c prose with the numbers inline, so the writer *lifts* each number into a
    placeholder before using the fragment.
- **Gates.** Small-cell suppression is applied while the model is built. The claim guard reads the
  finished model, and the export refuses on any `block` row.
- **Rendering.** officer / flextable turn the model into docx:
  - every `E` placeholder becomes a bookmark `sr_E<n>`;
  - captions use SEQ fields that carry a cached result;
  - the audit-chain tip goes in a custom document property and the footer.
- **Export.** `sr_export(project)` writes one numbered folder under `out/exports/` and records a
  `doc.exported` event.

**Tech Stack:** R 4.5.2; officer 0.7.3, flextable 0.9.11, xml2, zip (all installed); ggplot2 / ragg
through the existing `sr_plot` / `sr_figure_save`; testthat 3e. **No new packages.** Add `"officer"`
and `"flextable"` to `.sr_core_pkgs()` (`core/libsnap.R`) so the lockfile and the run snapshot
record them.

## Global Constraints
- **All P1a-P1c.1 Global Constraints still apply.**
  - Naming: `sr_` prefix for exported functions, `.sr_` for internal ones.
  - Files: ASCII-only `.R` with LF line endings. Generated `analysis.R` is ASCII too. Never run
    multi-line `Rscript -e`.
  - Data: synthetic or public package data only; tests write under `withr::local_tempdir()`; JSON
    via `.sr_json`; no table column named like a p-value.
- **Every new `app/R/**` file is appended to `.sr_core_files` in `app/global.R`,** after
  `"resample/feas_sim"`, in this order: `"writer/placeholders"`, `"writer/sdc_out"`,
  `"writer/fragments"`, `"writer/tables"`, `"writer/figures"`, `"writer/cite"`,
  `"writer/checklist"`, `"writer/model"`, `"writer/guard"`, `"writer/docx"`, `"writer/script"`,
  `"writer/sapdoc"`, `"writer/export"`.
- **Command prefix:** `RS="/c/Program Files/R/R-4.5.2/bin/Rscript.exe"`.
  - One test file: `"$RS" tools/run_tests.R <filter>`.
  - Whole suite: `"$RS" tools/run_tests.R` (30+ min; run it in the background).
  - Lint: `"$RS" tools/lint.R` → `LINT OK (N files)`.
- **The public repo carries no personal details.** No usernames, emails, hostnames or absolute user
  paths in any committed file, generated script or docx property. The docx `creator` is
  `"StatRouter"`, never the OS user.
- **Air-gap.** No network call anywhere. Package citations come from the installed
  `utils::citation()`. Method references come from the bundled file. Nothing is looked up online.
- **Models route; they never compute or write numbers.**
  - Every digit in the output comes from a registry placeholder whose source is evaluated R output.
  - A digit in a template outside a placeholder is a guard `block`.
- **Placeholder tokens** (the only `{{...}}` forms):
  - `{{E<n>}}`: a number or a numeric text, bookmarked;
  - `{{L<n>}}`: a data-derived label (variable, level, term, analysis id), not bookmarked;
  - `{{C:<key>}}`: a citation, rendered as a Vancouver number `[k]` in order of first use in the
    main document.

  `SR_PH_RE <- "\\{\\{(E[0-9]+|L[0-9]+|C:[a-z][a-z0-9_]*)\\}\\}"`.
- **The number token** (shared by lift and guard):
  `SR_NUM_RE <- "(?<![A-Za-z0-9_.])[-]?[0-9]+(?:\\.[0-9]+)?%?(?![A-Za-z0-9_])"` (perl = TRUE).
  - A digit inside an identifier (`z1`, `age_10`, `x2.b`) is not a number.
  - The guard tests a template with every `SR_PH_RE` token removed first.
- **Small cells:** `SR_SDC_K <- 5L`. A count of 1-4 prints as `"<5"`. Zero is not suppressed.
- **Event type added:** `doc.exported` {kind = "manuscript" | "sap" | "feasibility", id, files =
  [{path (relative to the project folder), sha}], audit_tip, sap_hash, preset}. Its reducer appends
  to `state$exports` (a list, in order).
- **Export folders:** `out/exports/<id>/`, where `id = sprintf("export-%03d", k)` and k is one more
  than the number of manuscript exports in `state$exports`. A folder is never overwritten: if it
  already exists, the export refuses.

## Review Focus
1. **A count of 1-4 escapes through a side door.**
   - The side doors:
     - a Table 1 cell such as `"3 (1.2%)"`;
     - the "Overall" cell, which gives back a suppressed group cell by subtraction;
     - the last suppressed cell in a categorical block, recoverable from the column total;
     - a fragment such as "4 events";
     - the KM number-at-risk strip;
     - the `value` field written to `placeholders.json`.
   - Expected: every one prints `"<5"`. Secondary suppression leaves no single suppressed cell in a
     row or a categorical block. `placeholders.json` carries `suppressed: true` and no value.
   - Pinned: Task 2 (cells and strip), Task 3 (route tables), Task 4 (fragment counts), Task 10
     (json).
2. **Data labels that look like numbers or markup.**
   - Examples: a level `"65+"`, a variable `z1`, a term `"x = 1 vs 0"`, a level holding `&`, `<`
     or `é`.
   - Expected:
     - labels reach templates only as `{{L}}` tokens, so the guard never flags them;
     - a fragment's `"65+"` lifts to an `E` placeholder that still resolves;
     - the docx is valid XML (re-read by `officer::read_docx`) and shows the characters unchanged.
   - Pinned: Task 1 (lift), Task 6 (guard), Task 8 (docx).
3. **Edited or polished text over-claims.**
   - Examples: "x reduces y" from a describe route; "significantly higher" on an estimate below the
     null; "no difference" on any result; "confirms" in a post hoc analysis; a covariate's estimate
     quoted in a causal design.
   - Expected: each one is a guard `block` naming its rule and paragraph, and `sr_export` refuses,
     listing them all.
   - Pinned: Task 6 (rules), Task 10 (export refusal).
4. **The project is not fully run.**
   - Cases: a primary analysis whose latest run failed; a secondary analysis never run; a cached
     fit deleted from `fits/`.
   - Expected:
     - the export refuses, naming the primary analysis, or naming the analysis whose cache is gone
       ("run it again");
     - a secondary analysis that never ran is listed under "Not reported" and scores amber in
       STROBE.
   - Pinned: Task 4 (model), Task 7 (STROBE amber), Task 10.
5. **Export twice, or export after a new run.**
   - Expected:
     - unchanged content gives the same placeholder ids, the same bookmark names and the same
       `sr_docx_digest`;
     - the second export writes `export-002` and never overwrites `export-001`;
     - bookmark names are unique, at most 40 characters, and match `^sr_[EL][0-9]+$`.
   - Pinned: Task 8 and Task 10.

Further cases a reviewer should probe, each pinned in its task:
- **An inadequate-tier analysis decided exploratory.** The Methods state why (the decision reason),
  and its Results need hypothesis-generating language (Task 4, Task 6).
- **A fired `replace_primary` rule.** The alternative is reported as primary, and the replaced
  analysis as sensitivity (Task 4).
- **A bootstrap result whose p is NA.** No p clause; "significant" is blocked (Task 4, Task 6).

**Interfaces:**
- Produces:
  - **`sr_ph_registry() -> environment`** of class `"sr_ph"`. It holds a data.frame `rows` with
    columns id, kind, text, value, analysis, source, scale, null, suppressed.
    - id is `"E<n>"` or `"L<n>"`.
    - kind is one of est, ci, p, count, num, text, label.
    - value is numeric or NA. scale is `"ratio"` / `"difference"` / NA. null is 1, 0 or NA (the
      no-effect value, used by the guard's direction rule).
  - **`sr_ph_put(reg, text, kind, source, analysis = NA, value = NA, scale = NA, null = NA,
    suppressed = FALSE) -> chr`** returns the token.
    - An existing `(source, kind)` pair returns its token unchanged.
    - kind `label` takes the next `L` number; every other kind takes the next `E` number.
    - Numbers are assigned in order of first put, so the same build order gives the same ids.
  - **`sr_ph_table(reg) -> data.frame`**: the rows, in id order (E rows, then L rows, each by
    number).
  - **`sr_ph_resolve(x, reg, cite = NULL) -> chr`** replaces every `E` / `L` token with its text.
    `cite` is a function(key) returning `"[k]"`; when it is NULL, `C` tokens are dropped. An
    unknown token is an error naming it.
  - **`sr_ph_lift(text, reg, source_prefix, analysis) -> chr`**:
    - every `SR_NUM_RE` match in `text` becomes a placeholder;
    - its source is `paste0(source_prefix, ":", k)`, where k is the match's position;
    - kind is `count` for a whole number without `%` whose next word (skipping one `(`) matches
      `SR_SDC_COUNT_WORDS = "^(rows?|row\\(s\\)|events?|cases?|participants?|patients?|deaths?|subjects?|observations?|excluded)\\b"`;
      every other number is `num`. A knot count or a bootstrap B is therefore never suppressed as a
      small cell;
    - value is the parsed number (the `%` dropped).
  - **`sr_ph_digits(template) -> chr`**: the `SR_NUM_RE` matches left once the `SR_PH_RE` tokens
    are removed.
  - **Resolvers:** `.sr_ph_resolvers` is an environment of resolver functions keyed by the source
    prefix (the text before the first `:`). Each resolver takes `(project, parts, kind)` and
    returns the text. This task registers:
    - `effect:<analysis>:<row>:<field>`, where field is est / lo_hi / p / n / events. est and
      lo_hi use the decimals of `sr_fmt_ci(est, lo, hi, mcse)`: est is the part before " (" and
      lo_hi the part inside the brackets. p uses `sr_fmt_p`; n and events use `sprintf("%d")`.
    - `fragment:<analysis>:<name>:<k>`: the k-th `SR_NUM_RE` match in that fragment of
      `sr_result()`.
    - `label:<text>`: the text itself.
  - `.sr_ph_register_resolver(prefix, fn)` is how later tasks add their resolvers.
  - **`sr_ph_verify(reg, project) -> data.frame(id, source, expected, got, ok)`**:
    - re-derives every row from its source;
    - a suppressed row passes when the re-derived count is in 1..(SR_SDC_K - 1);
    - a resolver error becomes `ok = FALSE` with the message in `got`.
  - `SR_PH_RE`, `SR_NUM_RE` (Global Constraints).
- **Fixture.** `helper-writer.R` defines `.fx_writer_project(env)`. Build it once per R session and
  cache it: copy a template project folder made under `tempdir()` into a fresh
  `withr::local_tempdir()` for each caller, then `sr_project_open` it.
  - **The data.** A synthetic frame, `set.seed(11)`, n = 400:
    - `id`;
    - `grp` (A/B), the exposure;
    - `age` (normal 60, 10) and `z1` (binary);
    - `stage` (I/II/III, with III on exactly 3 rows, so small cells exist);
    - `y` (binary "yes"/"no", logistic in `grp`, `age`, `z1`);
    - `time` / `status` (exponential, about 30% censored);
    - a level label `"65+"` in a factor `agecat`.
  - **The analyses**, in this order:
    - `t1`: table1 by `grp` over `age`, `z1`, `stage`, `agecat`; primary.
    - `a_lr`: logistic `y ~ grp + age + z1`, marginal on; primary; family `fam1`.
    - `a_cox`: cox on `time` / `status` ~ `grp + age`; secondary; family `fam1` (holm).
    - `a_rmst`: rmst, tau = the 80th percentile of `time`; secondary.
    - `a_mp`: modpois of the same model; sensitivity.

### Task 2: Small-cell suppression

**Files:**
- Create: `app/R/writer/sdc_out.R`, `tests/testthat/test-writer-sdc.R`
- Modify: `app/R/diagnostics/plots.R` (the km strip), `tests/testthat/test-plots.R`, `app/global.R`

**Interfaces:**
- Consumes: `SR_SDC_K`; registry rows (Task 1).
- Produces:
  - **`.sr_sdc_count(cell) -> integer`**: the count a text cell shows, or NA when it is not a count
    cell. A count cell matches `^[0-9]+$` or `^[0-9]+ \([0-9.]+%\)$`.
  - **`sr_sdc_table(df, k = SR_SDC_K, block_col = 1L, skip_cols = character()) -> list(table,
    n_suppressed)`**:
    - **Primary suppression:** every count cell with a count of 1..(k-1) becomes `"<5"` (the
      text is `paste0("<", k)`).
    - **Row rule:** over the non-`skip_cols` count cells of one row, excluding a column named
      `"Overall"`, a row with exactly one suppressed cell also suppresses its smallest other
      non-zero count cell. When any group cell of the row is suppressed, the Overall cell keeps
      its value.
    - **Block rule:** a categorical block is the run of consecutive rows whose `block_col` cell
      starts with four spaces (the table1 level rows). Within one column of a block, exactly one
      suppressed cell also suppresses the smallest other non-zero count cell of that column in
      the block.
    - The two secondary rules repeat until nothing changes.
    - `n_suppressed` counts all suppressed cells.
  - **`sr_sdc_value(x, k = SR_SDC_K) -> list(text, suppressed)`** for one count: `"<5"` / TRUE for
    1..(k-1), otherwise `sprintf("%d", x)` / FALSE.
  - **`sr_sdc_km_risk(km_risk, k = SR_SDC_K) -> data.frame`**: adds a character `label` column,
    `"<5"` for n.risk of 1..(k-1) and the integer text otherwise.
  - **plots.R:** the km strip draws `label` when the column exists, else `n.risk` as now. Update
    the header comment.
- Rulings:
  - Zero is shown. The spec suppresses small *non-zero* cells.
  - The Overall column is never the cell suppressed by the row rule. The row rule hides a second
    group cell, so the Overall cell no longer gives the hidden one back by subtraction.

  - **`sr_claim_check_text(text, analysis, model) -> same frame`**, for one edited or polished
    sentence. It is what the guard calls per block, and what P2 / P3 call on user text.
- **Rules** (lexicons are constants in `guard.R`, matched case-insensitively on word boundaries).
  - **G1 `digits` (block):** `sr_ph_digits(text)` is non-empty.
  - **G2 `causal_language` (block),** for a route whose purpose is not explain-causal. Lexicon
    `SR_GUARD_CAUSAL`: cause, causes, caused, causal, effect of, effects of, leads to, led to,
    results in, resulted in, reduces, reduced, increases, increased, prevents, prevented,
    protective, impact of, attributable to, due to.
  - **G3 `risk_factor` (block),** for purpose predict: "risk factor", "determinant".
  - **G4 `significance` (block):**
    - "significant" / "significantly" / "non-significant" / "not significant" in a sentence with
      no `E` placeholder of kind p;
    - "significant(ly)" when that p value >= alpha;
    - "not significant" / "non-significant" when p < alpha;
    - any use for a describe purpose.
  - **G5 `absence_of_evidence` (block):** "no difference", "no effect", "no association", "did
    not differ", "was not associated", "were not associated".
  - **G6 `direction` (block):** a sentence with exactly one `E` placeholder of kind est whose
    registry row has a finite value and a non-NA null.
    - Increase words (higher, greater, increased, more, elevated, longer) contradict
      `value < null`.
    - Decrease words (lower, reduced, decreased, fewer, less, shorter) contradict `value > null`.
    - With two or more est placeholders in one sentence, the guard issues `warn` "direction not
      checked".
  - **G7 `hypothesis_generating` (block),** for an analysis whose wording is exploratory:
    - each of its Results sentences must contain "exploratory" or "hypothesis-generating";
    - none may contain a confirmatory word (`SR_GUARD_CONFIRM`: confirm, confirms, confirmed,
      demonstrate, demonstrates, demonstrated, establish, establishes, established, prove,
      proves, proved, definitive).
  - **G8 `table2` (block):** a sentence that holds an `E` placeholder whose source is an effects
    row with role covariate, for an explain-causal route.
  - **G9 `non_collapsible` (warn):** a sentence with an OR / HR est placeholder from a conditional
    row that contains neither "conditional" nor "adjusted".
- Registry rows need the null for G6. Set them in Task 4 when the est placeholder is put: 1 for
  ratio, 0 for difference. That field is already in the Task 1 schema.

    `props` = list(audit_tip, sap_hash, export_id, created). Each block renders as:
    - **heading:** a Word heading style.
    - **para:** an `fpar` of `ftext` runs, in the preset font. The template is split on
      `SR_PH_RE`.
      - Each `E` token is a `run_bookmark(paste0("sr_", id), ftext(text))`.
      - Each `L` token is a plain run.
      - Each `C` token is `[k]` from `sr_cite_order(model)`.

      - a caption paragraph `"Table <SEQ Table> . <caption>"` before the table, or `"Table S<SEQ

        cells;
      - the footnotes as small paragraphs after the table.
    - **figure:** the PNG from `sr_wr_figure_render(block, fig_dir, preset)` via `external_img` at
      the preset's width, then a caption `"Figure <SEQ Figure>. <caption>"` (`"Figure S<SEQ
      FigureS>"` in the supplement).

    - **checklist:** a flextable with a status cell coloured green #C6EFCE / amber #FFEB9C / red
      #FFC7CE.

    ARABIC` whose *cached result* is the computed number (1, 2, ... in document order). The number
    shows without updating fields. The mechanism is free; the suggested one is to write the
    caption with officer, then patch `word/document.xml` with xml2 in `.sr_docx_patch(path,
    fun)`.

  - **`sr_docx_bookmarks(path) -> data.frame(name, text)`:** the text between each
    `w:bookmarkStart` and its `w:bookmarkEnd`, read with xml2 from `word/document.xml`.
  - **`sr_docx_digest(path) -> chr`:** the SHA-256 over the sorted (part name, bytes) of the docx.
    - `docProps/core.xml` dates are replaced by a fixed string.
    - Media part names are replaced by the sha of their bytes, with the relationship targets
      rewritten to match.
    - The same model gives the same digest even though the zip timestamps differ.
- **Ruling: Determinism is defined by the digest, not by file bytes.** officer stamps the time and
  may name media randomly. The freeze manifest (P1d freeze) hashes the files as they are.
