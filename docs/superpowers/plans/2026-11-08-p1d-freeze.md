# P1d.3 Freeze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze a locked, run project into a named snapshot (`submission-v1`, `revision-r1`), export it
as a drive-letter-independent `.srproj` archive, import it at another path with identical hashes, and
refuse to recompute under a changed library until an explicit re-baseline with a diff report.

**Architecture:** One headless layer under `app/R/archive/`.
- **Freeze** (`freeze.R`). `sr_freeze()` checks the gate, then writes `out/freezes/<label>/` atomically
  (through a `.partial` folder). The folder holds `manifest.json`, `analysis.R` and `renv.lock`.
  - The manifest lists every frozen file with its SHA-256: store manifests and parts, in-project
    sources, extracts, the fits of the ok runs, the export files and the two code files.
  - It also records the events prefix hash, the audit tip, the SAP hash, the library snapshot, each
    table's store hash and version, and the ok run of each analysis.
  - A `freeze.created` event carries the manifest's SHA-256. Its own audit entry chains that hash
    into `audit.log`.
- **Library baseline** (`baseline.R`). The latest freeze, or the latest re-baseline, is the
  *baseline*.
  - `sr_run` refuses to run under a library hash other than the baseline's.
  - `sr_rebaseline()` needs a reason. It records the old and new snapshot and the package diff
    (`freeze.rebaselined`).
- **Archive** (`tar.R`, `srproj_export.R`, `srproj_import.R`).
  - A `.srproj` file is a gzip tar written with R's internal tar. It holds `srproj.json` (the index:
    every member with its SHA-256) and the project folder *as it was at the freeze*. `events.jsonl`
    and `audit.log` are cut just after the `freeze.created` event, and later exports, runs and freezes
    are left out.
  - The archive is built in a staging folder with hard links (copy fallback), then tarred, re-scanned
    and renamed into place.
  - Import scans the tar headers first (regular files and folders only, safe relative names), extracts
    to `<dir>.partial`, then checks every member against the index. It renames, opens the project and
    runs `sr_freeze_verify()`. Anything wrong removes the extracted folder and errors.
- **Diffs** (`diff.R`).
  - `sr_freeze_diff()` compares two freezes, or a freeze and now: tables and their re-imported
    versions, which is the data-versioning view, plus the library, the SAP hash and the analyses.
  - `sr_freeze_results_diff()` compares the frozen numbers with the current ones after a re-baseline.

**Tech Stack:** R 4.5.2; `utils::tar(tar = "internal", compression = "gzip")` and
`utils::untar(tar = "internal")`, which are pure R (the locked PC has no `zip` program); `openssl`
through the existing hash helpers; testthat 3e. **No new packages.**

## Review Focus
1. **A tampered archive.** One byte changed in an extract or a fit, a line edited in
   `events.jsonl`, or a member added that the index does not list. Import must refuse and leave no
   folder behind: neither `<dir>` nor `<dir>.partial`. (Task 5)
2. **A hostile tar member.** `../x`, `/x`, `C:/x`, a backslash, or a symlink or hard-link entry. Import
   must refuse before it extracts anything. (Tasks 3 and 5)
3. **Work after the freeze.** New runs, a re-import and another export happen after the freeze, and
   the project is then archived. The archive must still be the project as it was at the freeze, and
   the imported project shows only the freeze-time results and events. (Task 4)
4. **An export that fails halfway.** For example, tar errors or the disk fills. No `.srproj`, no
   `.srproj.partial` and no staging folder may be left, and no event appended. (Task 4)
5. **A lean archive.** It holds no parts and no sources. The import must succeed and list the tables
   whose parts are absent. `sr_result()` must still return every frozen result. `sr_freeze_verify()`
   must report the absent data files as absent, not as problems. (Task 5)

    7. an ok run whose fit or extract file is missing: "the stored result of 'x' is missing; run it
       again" (for an extract, "the extract of 'x' is missing ...");
    8. `sr_project_verify` is not ok, or reports `unaudited`: "the project does not verify: ...".
  - **Run ids.** The ids are the analyses whose run has a non-NA `ok_key`, in state order.
  - **Code files.** `analysis.R` is `sr_analysis_script(project, ids)`. `renv.lock` is
    `.sr_json(sr_lockfile(snap, sr_lockfile_matches_runs(project, ids, snap)))` plus `"\n"`, with
    `snap <- sr_libsnap()`. Write both with `.sr_ex_write_text` into
    `out/freezes/.<label>.partial/`.
  - **Files list.** Build it in this order, each path relative and with forward slashes:
    1. every table's `data/store/<t>/manifest.json` (kind `store_manifest`), with the SHA-256
       computed;
    2. its parts (kind `part`), with the sha256 taken from the store manifest. The freeze does not
       rehash 100 GB, and `sr_freeze_verify` does;
    3. the in-project source of every non-derived, non-external table (kind `source`), with
       `entry$source$sha256`;
    4. each run's extract and fit (kinds `extract` and `fit`), deduplicated and hashed;
    5. every file under each finished `out/exports/export-*/` folder (kind `export`, hashed);
    6. the two code files (kind `code`).
    `bytes` is `file.size()`.
  - **Tables.** `tables[[t]]$base` and `$version` come from `state$reimports[[t]]` (`table` and
    `version`), or are `t` and `0L` for an original table. `rows` is the sum of the parts' rows.
  - **Write order.** Write `manifest.json` last into the partial folder with `.sr_write_json_file`.
    Hash it, then `file.rename` the partial folder to `.sr_freeze_dir`. Only then append
    `freeze.created`. An error before the rename unlinks the partial folder (`on.exit`).
  - **Events prefix.** `events$seq` is the seq of the last event before the append, which is
    `length(.sr_events_load(...)$events)` because seqs run 1..n. Its `sha256` is
    `.sr_events_prefix_sha(paths$events, seq)`. `audit_tip` is `sr_audit_tip(paths$audit)`, taken
    just before the append.
  - **Verify.** `sr_freeze_verify` returns problems in this order:
    1. the freeze is not in `state$freezes`;
    2. the manifest's SHA-256 differs from the event's;
    3. the events prefix hash differs;
    4. `audit_tip` is not the hash of the audit entry right before the `event:freeze.created` entry

    5. any present file's `sr_sha256_file` differs from the manifest;
    6. a missing file of a non-data kind.
    A missing data-kind file goes to `absent`. With `data = FALSE`, data-kind files are skipped:
    neither hashed nor reported. `checked` counts the files hashed.
  - **Reducer.** `freeze.created` stores the payload plus `ts` in `state$freezes[[label]]`. It sets
    `state$lib_baseline <- list(hash = libsnap_hash, snap = libsnap, from = "freeze", label = label)`.

**Interfaces:**
- Produces:
  - `.sr_tar_entries(path)` gives data.frame(name, type, size) for every member, in order. `type` is
    the one-character typeflag, with `"\0"` reported as `"0"`; `size` is double.
    - It reads gzip or plain tar through `gzfile(path, "rb")`.
    - It joins the ustar `prefix` and `name` with `/` when the magic is `"ustar"`.
    - It applies a GNU `L` long-name entry to the next member and does not list the `L` entry itself.
    - It decodes octal sizes, and base-256 sizes when the high bit of the first size byte is set.
    - It stops at the first all-zero block.

      and with "truncated tar archive" on a short read.
  - `.sr_archive_safe_path(x)` gives a logical vector. A name is safe when all of these hold:
    - it is non-empty, after dropping one trailing `/`;

    - it has no segment that is `""`, `.` or `..`.

    - "archive member '<n>' is a link or special file (type <t>)" for any type other than `"0"`
      or `"5"`;
    - "unsafe archive member name '<n>'";
    - "duplicate archive member '<n>'".

  - `sr_freeze_diff(project, from, to = NULL)` gives list(tables, library, sap, analyses). `to = NULL`
    compares with the project now.
    - `tables`: data.frame(table, base, version, change ∈ "added", "removed", "changed", "same",

  - `.sr_fz_numbers(x)` gives a named double vector of every numeric or integer leaf of `x`:
    `rapply(list(x), as.numeric, classes = c("numeric", "integer"), how = "unlist")`.
