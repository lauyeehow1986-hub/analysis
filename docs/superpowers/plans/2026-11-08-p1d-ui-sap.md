# P1d UI sub-project 1 (Design + SAP panels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Design and SAP panels. With them, a user goes from a confirmed Data panel to a locked SAP, with `SAP_v1.docx` written, without leaving the app.

**Architecture:**
- **Shared helpers.** `ui/util.R` holds an `act()` factory lifted out of `mod_data`, plus the card, table and banner helpers.
- **Form builder.** `ui/spec_form.R` is pure: it turns a route's `spec_schema` and a field-kind map into a form description, and turns form values back into a spec.
- **Two Shiny modules.**
  - `mod_design`: research question, router decision table, Ask Jev (connected mode only), shadow summary.
  - `mod_sap`: analyses, feasibility, families and rules, checklist, lock, documents.
- **State.** Every edit goes through `act()` to the existing core. Every view re-renders from the project the core returns.

**Tech Stack:** R 4.5.2, shiny 1.14.0, bslib, DT, testthat 3 (`shiny::testServer`), withr.

**Spec:** [docs/superpowers/specs/2026-11-08-p1d-ui-design-sap-design.md](../specs/2026-11-08-p1d-ui-design-sap-design.md). It is the authority. Read it before any task. Section numbers below (§) refer to it.

## Global Constraints

- **Run commands from the worktree root** `<repo root>/.worktrees/p1d-ui-sap`.
  - Rscript: `& "C:\Program Files\R\R-4.5.2\bin\Rscript.exe"`.
  - Never run long multi-line code through `Rscript -e`; write a script file under the scratchpad instead.
- **Run a single test file** with:
  `Rscript -e "source('tests/testthat/helper-load.R'); testthat::test_file('tests/testthat/<file>')"`.
  Use `testthat::test_dir('tests/testthat')` for the full suite. The full suite is slow: run it in the background.
- **Naming.** Exported functions use `sr_`, internal ones `.sr_`, in snake_case. UI helpers are `.sr_ui_*`.
  - Module pairs are `mod_design_ui(id)` / `mod_design_server(id, project, busy)` and `mod_sap_ui(id)` / `mod_sap_server(id, project, busy)`.
- **ASCII only.** All new and changed `.R` files are ASCII only. Build a non-ASCII UI glyph from code points (`intToUtf8(0x00B7)`), as `app.R` does.
- **Models never compute numbers.** The UI shows core output only.
- **Air-gap mode makes no network calls, ever.**
  - In air-gap mode no server code may call a Jev function, `sr_router_preview`, or `sr_router_run` with a backend.
  - `sr_router_run(project)` with no backends is allowed.
- **Read options** through `sr_opt(name, default)`. Never use a bare `getOption`.
- **No personal details in any committed file.** That means no usernames, emails, hostnames, or `C:\Users\<name>` paths.
  - Grep the diff for them before every commit: `git diff --cached | grep -inE "<your username>|users\\\\|@gmail"` must print nothing. Put the real username in the pattern locally; never commit it.
- **Commits.** Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- **Editing state.** `.sr_ui_editable(p)` is TRUE iff the project is open, not read-only, and the SAP is not locked. Every editing control on both panels is built with `disabled = !.sr_ui_editable(p)`.
  - The core refuses these edits anyway. Never rely on the disabled button.
- **Refusals.** A refusal raised by a dialog's action is rendered inside that dialog by a `*_err` text output, with the inputs kept. The dialog is closed only on success.

## Review Focus

These are failure modes the spec implies (§7) but that a happy-path test would not catch. Each one is pinned by a named test in its owning task.

1. **Unknown schema field.** A route whose schema gains a field the form does not know is refused with "the form cannot build field '<f>' of route '<r>' yet". It is never built without that field.
   Pinned by `test-ui-spec-form.R` "an unknown field refuses the route" (Task 3).
2. **Air-gap.** Nothing reaches the network in air-gap mode. In connected mode, only ticked payloads are sent, and a payload edited after preview is not sent as approved.
   Pinned by `test-mod-design.R` "air-gap: no Jev card, transport never called" and "only ticked SHAs are sent" (Task 5).
3. **Read-only.** A locked SAP or a read-only project cannot be edited from any control on either panel. Every `observeEvent` that edits goes through `act()`, and `act()` refuses read-only projects.
   - A locked SAP is refused by the core.
   - The test drives every edit input after the lock and asserts the event log did not grow.
   Pinned by "after the lock every edit is refused" (Task 8) and "read-only: every edit refused" (Tasks 4 and 6).
4. **Refused save.** A refused save keeps the user's inputs and shows the core's message verbatim in the dialog.
   Pinned by "a refused add shows the core message and keeps inputs" (Task 6) and "assess refusal shows in dialog" (Task 7).
5. **Failed `SAP_v1.docx` write.** If the docx write fails after a successful lock, the failure is reported, the lock stands, and a retry button writes it.
   Pinned by "a failed SAP_v1 write is reported and retried" (Task 8).

### Task 3: The pure spec-form builder

**Files:**
- Create: `app/R/ui/spec_form.R`
- Test: `tests/testthat/test-ui-spec-form.R`

**Interfaces:**
- Consumes: `sr_routes()`, `sr_route_get(id)`, `sr_router_choice(p, node, table, column)`, `sr_roles(p, table)`, `sr_spec_validate(spec, route)`, the table's column names, `SR_LAYER_SETS`, `SR_LAYER_FLAGS`.
  - The implementer finds how `mod_data` reads the column names of table `t` and reuses it.
- Produces:
  - `SR_FORM_KINDS`: a named chr vector, field name to kind, with exactly these entries:

    | Kind | Fields |
    |---|---|
    | `column` | `outcome`, `exposure`, `cluster`, `time`, `status`, `strata`, `by` |
    | `columns` | `vars`, `nonnormal` |
    | `terms` | `terms` |
    | `interactions` | `interactions` |
    | `layers` | `layers` |
    | `enum` | `se`, `standardize_over`, `ties`, `penalty` |
    | `logical` | `marginal` |
    | `number` | `seed`, `tau` |
    | `text` | `event_value` |
    | `event` | `status_event` |
    | `hidden` | `exclude_rows` |

  - `SR_FORM_EXTRAS`: a list of the form fields outside the schema. Each entry is `list(id, kind, label, when, to)`:

    | `id` | `kind` | `when` (route / layer condition) | `to` (spec path) |
    |---|---|---|---|
    | `exposure_ref` | `text` | the route has an `exposure` field | `exposure_ref` |
    | `mi_m` | `text` | `layers$missing == "mi"` | `mi$m` |
    | `mi_maxit` | `number` (default 10) | `missing == "mi"` | `mi$maxit` |
    | `mi_aux` | `columns` | `missing == "mi"` | `mi$aux` |
    | `boot_B` | `number` (default 2000) | `resampling == "bootstrap"` | `boot$B` |
    | `boot_type` | `enum` `percentile`/`bca`/`normal` | `resampling == "bootstrap"` | `boot$type` |
    | `boot_cluster` | `logical` | `resampling == "bootstrap"` | `boot_type = "cluster"` when TRUE |
    | `mi_x_boot` | `enum` `boot_then_impute`/`impute_then_boot` | MI and bootstrap both on | `choices$mi_x_boot` |

    Notes:
    - `mi_m` parses as a whole number when numeric, else is kept as `"auto"`.
    - `when` in the table is a function `(route_id, layers)`. Because it depends on the layers, the form is rebuilt when a layers select changes.
  - `sr_spec_form(route_id, table, project)` returns a list of field entries in schema order, then the extras.
    - Each entry is `list(id, kind, label, required, choices, disabled, default, value, source)`.
    - The `layers` entry is one entry per layer: id `layers_<name>`, its choices, and `disabled`, a named chr of reasons for values P1 cannot run.
      - Disabled with the reason `"not runnable in P1"`: weights `ipw`, `overlap`, `survey`; matching `TRUE`; framework `bayesian`, `both`.
      - Layer defaults: `missing = "cc"`, `weights = "none"`, `matching = FALSE`, `resampling = "none"`, `framework = "frequentist"`, `clustered = FALSE`.
    - `hidden` fields produce no entry.
    - `purpose` is never an entry. It comes from the route (`sr_routes()$purpose`).
    - The number default of `seed` is `42`.
    - It stops `"the form cannot build field '<f>' of route '<r>' yet"` when a schema field is not in `SR_FORM_KINDS` and not `purpose`.
  - `sr_spec_collect(route_id, values)` returns a spec list. `values` is a named list keyed by entry id.
    - It drops NULL, `""`, zero-length and NA values of optional fields.
    - It builds `layers` from the `layers_*` ids, casting `matching` and `clustered` to logical.
    - It builds `terms` from `values$terms`, a list of `list(var, type, knots)`. Empty knots become NULL, one number stays a number, and a comma list becomes numeric locations.
    - It builds `interactions` from a list of length-2 chr vectors.
    - It casts `number` kinds with `as.numeric`.
    - For `event`: numeric when `!is.na(suppressWarnings(as.numeric(x)))`, else the string.
    - It maps the extras through `to`, keeping only the extras whose `when` is TRUE.
    - It adds `purpose`.
    - It does no validation.
- **Prefill order** for `value`/`source`:
  1. Router. Only decided, current choices from `sr_router_choice` are used; stale or undecided ones never are.
     - `purpose`.
     - `outcome` from node `outcome_col` (table).
     - `exposure` from `exposure_col` (table).
  2. Roles.
     - outcome from the `outcome` role; exposure from `exposure`; cluster from `cluster`; time from `time`; status from `event`.
     - `terms` from the `covariate` roles, each `type = "linear"`.
     - table1 `by` from `exposure` and `vars` from the covariates.
     - `layers_clustered = TRUE` when a cluster role exists.
  3. Schema or form default (`source = "default"`).
  4. Otherwise `value = NULL`, `source = NA`.

  - Add one helper, `sr_spec_form_route(project, table)`, which returns the decided `primary_route` choice, or NA when it is undecided, stale or `"none"`. The builder dialog uses it to preselect the route.
  - The implementer reads `sr_router_choice`'s return shape in `engine.R` to tell decided from stale.

## Deviations from the spec, decided here

- **`.sr_data_try` stays as a wrapper** of `.sr_ui_try`, because an existing test calls it and §6 says `test-mod-data.R` passes unchanged.
- **Disabling controls.** Editing controls are disabled by re-rendering them with `disabled`, not with shinyjs, so `testServer` can assert it from output HTML.
- **Shadow export.** Uses `.sr_ui_try` rather than `act`, because it writes a file and returns a path, not a project. It keeps the same three refusals.
- **Gate lines.** `.sr_design_gates` repeats the four gate checks of `.sr_jev_available` so that all four can show at once. The core gate stays authoritative at send time.
