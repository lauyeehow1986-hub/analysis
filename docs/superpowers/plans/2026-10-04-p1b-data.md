# P1b Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take a raw file (any catalogue-J format, up to 100 GB) and produce analysis-ready data
inside a StatRouter project. The user can:
- import a file by path, with a pre-flight check, a resumable streamed ingest into the project's
  Parquet store, and external-data mode;
- attach a dictionary (generic, REDCap CSV, REDCap ODM XML, or SPSS/Stata/SAS labels);
- join tables with a key report, and build a cohort from long data;
- confirm variable roles;
- run out-of-core profiling and the catalogue-A DQ checks, outcome-blind until the SAP is locked;
- act on each finding through the Data Action Suggestor: a cleaning recipe with undo and
  branching, a data-query sheet with re-import diff, and a flow diagram;
- see a readiness panel that lists what still blocks analysis.

**Architecture:** This plan adds headless modules under `app/R/io/`, `app/R/intake/` and
`app/R/profile/`, plus one Shiny module, `app/R/ui/mod_data.R`. They all sit on the P1a core.
- **Engine.** DuckDB, in memory, is the only SQL engine. It reads sources and project Parquet
  parts, and it is locked down so it can never fetch or load an extension.
- **Store.** Every table lives as Parquet parts plus a `_manifest.json` under `data/store/<table>/`.
- **Events.** Every accepted action is a project event with a registered reducer. Large artefacts
  (findings, profiles, samples) are files whose SHA-256 the event records.
- **Code-first.** The recipe and the cohort builder compile to SQL strings. That SQL is what runs,
  and it is what gets exported later.

**Tech Stack:** R 4.5.2, duckdb 1.4.x + DBI, openssl, jsonlite (`parse_json` / `stream_in` only),
readxl, writexl, haven, xml2, RSQLite, arrow (optional; Feather/IPC only), consort + ragg,
shiny/bslib/DT/shinyFiles, mirai (ExtendedTask in the UI), testthat 3e.

**Spec:** `docs/specs/2026-10-03-statrouter-design.md`. Relevant sections:
- catalogue **J** (import and very large files);
- catalogue **A** (profiling and DQ);
- catalogue **A+** (Data Action Suggestor);
- Phases → **P1** items 1 and 3, and the P1 Exit criterion on planted defects;
- Verification → "Import / large-data checks", "Pre-lock views contain no outcome-by-exposure
  statistic", "Profiler: planted-defect recall and clean-twin false-positive rate".

**Builds on (P1a, on `main`):**
- Options and helpers: `sr_opt`, `sr_mode`, `.sr_now`, `.sr_json`, `.sr_parse_json`, `.sr_sha256`,
  `.sr_write_atomic(path, bytes)`, `.sr_read_bytes`.
- Events: `sr_reducer_register(type, fn)`, `sr_project_append(project, type, payload)`, which
  returns the project with `$state` updated.
- Project: `sr_project_create(dir, name, profile, mode)`, `sr_project_open(dir)`,

- Hardware and hashing: `sr_profile_caps(profile)` (fields `$duckdb_memory_gb`, `$duckdb_threads`,
  `$ram_budget_gb`, `$workers`), `sr_canonical_json`, `sr_content_hash`.
- Lint: `sr_lint_airgap(files)`.

**Out of scope here** (each is a ruling; the owning phase is in brackets):

- System One role inference [P1d]. P1b's role suggestions are rules only.
- pyreadstat chunking for SAS/Stata/SPSS [P12 bundle]. P1b uses haven `skip` / `n_max` chunks.
- Little's MCAR test and the missingness models used by imputation [P1c, catalogue D].
- Riley sample-size criteria [P6, prediction].
- the informative-censoring screen [P1c, survival route].
- long/wide reshape [P9].

## Global Constraints
- All P1a Global Constraints still apply:
  - `sr_` prefix for exported functions, `.sr_` for internal ones;
  - ASCII-only `.R` files with LF line endings; non-ASCII test strings built with `intToUtf8()`;
  - never multi-line `Rscript -e`;
  - synthetic data only; tests write under `withr::local_tempdir()`;
  - JSON written via `.sr_json`; ISO-8601 UTC milliseconds timestamps.
- Command prefix: `RS="/c/Program Files/R/R-4.5.2/bin/Rscript.exe"`.
  - Single test file: `"$RS" tools/run_tests.R <filter>` (Task 1 adds the filter argument).
  - Whole suite: `"$RS" tools/run_tests.R`.
  - Lint: `"$RS" tools/lint.R` → `LINT OK (N files)`.
- **The public repo carries no personal details.** No usernames, emails, hostnames, or absolute
  user paths in any committed file. Fixtures use `withr::local_tempdir()` paths only.
- **DuckDB is locked down at connect time (air-gap).** Probe on 2026-10-04: duckdb 1.4.3 bundles
  `parquet` and `core_functions` but **not `json`**. `httpfs` sits installed in the dev laptop's
  user cache, and `INSTALL` / `LOAD` still succeed after `lock_configuration`. So every connection:
  - opens with `SET extension_directory` pointing at an empty `data/tmp/duckdb_ext` folder (owned
    by the project);
  - sets `autoinstall_known_extensions=false`, `autoload_known_extensions=false` and
    `allow_community_extensions=false`;
  - then sets `lock_configuration=true`.

  All app SQL goes through `sr_duck_exec` / `sr_duck_query`. These refuse:
  - any statement that starts with `INSTALL`, `FORCE INSTALL`, `LOAD`, `SET`, `RESET`, `PRAGMA`
    or `ATTACH`, except the connection's own setup;
  - any string literal matching `'[A-Za-z][A-Za-z0-9+.-]*://`.

  Never read JSON with DuckDB `read_json`: use `jsonlite::stream_in` on a `file()` connection.
  Never use DuckDB's sqlite extension: use RSQLite.
- **Paths are never URLs.** `sr_sniff` refuses `^[A-Za-z][A-Za-z0-9+.-]*://` before any read.
  Windows UNC paths (`\\server\share`) are allowed but flagged as a network share.
- **SQL identifiers and literals are always quoted** with `DBI::dbQuoteIdentifier` /
  `DBI::dbQuoteString`. Build SQL by quoting, never by pasting user text.
- **Table names** match `^[a-z][a-z0-9_]{0,62}$`. `sr_table_name(path)` derives one from the file
  name: lowercase it, turn non-alphanumerics into `_`, prefix `t_` when it starts with a digit,
  and add a `_2`, `_3`, ... suffix on collision.
- **Event types added by P1b**, each with a reducer registered in the file that owns it:
  - `data.imported`, `data.source_hashed`, `data.source_relocated`, `data.reimported`;
  - `dict.set`, `join.created`, `cohort.built`, `roles.set`, `dq.run`, `action.decided`;
  - `recipe.step`, `recipe.undo`, `recipe.branch`, `recipe.checkout`;
  - `query.exported`.
- **State keys:** `state$tables[[t]]`, `state$dict[[t]]`, `state$joins[[t]]`, `state$cohorts[[t]]`,
  `state$roles`, `state$dq[[t]]`, `state$actions[[finding_id]]`, `state$recipe`, `state$flow`.
- **Paths stored in events** are relative to the project dir (forward slashes), except an external
  source's path, which is stored as given (absolute) plus its fingerprint.
- **Outcome-blind rule.** `sr_blind(project)` is `!isTRUE(project$state$sap$locked)`. While it
  is blind:
  - no function returns any statistic that involves both an outcome-role column and any other
    column;
  - leakage and separation are reported as flags with no AUC, counts or estimates;
  - outcome columns get completeness and plausibility only.
- **Severities:** `info < warn < block`. A `block` finding blocks analysis until an action is
  decided for it.
- **Every DQ threshold is an effect size**, never a p-value alone. Large n must not make checks fire.

## Review Focus
1. **A process is killed half-way through a multi-GB CSV ingest (or the USB drive is unplugged).**
   - Expected: reopening and calling `sr_ingest` again resumes from the last committed part.
   - No part is duplicated or missing.
   - The final row count equals the source, and the store hash equals that of an uninterrupted
     ingest.
   - Pinned in Task 5.
2. **A column's type changes deep in the file** (e.g. `"7.5"` in an INTEGER column at row 4M, or
   `"pending"` in a numeric lab column).
   - Expected: the ingest never silently NULLs the value.
   - The column is widened to VARCHAR across *all* parts (restart with a ledgered reason).
   - Profiling then reports the coercion failures with examples.
   - Pinned in Task 5 and Task 13.
3. **A quoted field contains embedded newlines** (free-text notes), and byte-range chunking would
   split a record.
   - Expected: sniff detects quoted newlines and ingest falls back to a single DuckDB pass
     (`resumable = FALSE`, logged).
   - Row count and content equal the source.
   - Pinned in Task 5.
4. **Profiling or the Suggestor leaks outcome information before the SAP lock**, e.g. a
   `table(outcome, exposure)`, an AUC value, or a missingness model with the outcome as a
   predictor.
   - Expected: every pre-lock output passes `.sr_assert_blind()`, which recursively finds no
     outcome-crossing statistic.
   - Pinned in Tasks 12, 15 and 18.
5. **A non-UTF-8 file** (Latin-1 `µmol/L` in a header, or a UTF-16 BOM export from Excel) **or a
   DMY/MDY ambiguous date column.**
   - Expected: the encoding is detected and converted, so headers and values round-trip byte-exact
     to UTF-8.
   - An ambiguous date order is flagged and never silently guessed when no value disambiguates it
     (all day values <= 12).
   - Pinned in Task 2.

### Task 2: Format and dialect sniffing

**Files:** Create `app/R/io/sniff.R`, `tests/testthat/test-sniff.R`. Modify `app/global.R` (add `io/sniff`).

**Interfaces:**
- Produces `sr_sniff(path, sample_bytes = 1048576L) -> list(...)` with these fields:
  - `path`: normalised;
  - `format` ∈ `csv | parquet | feather | rds | rdata | fst | ndjson | json | sqlite | duckdb | xlsx | xls | sav | por | dta | sas7bdat | xpt | odm`;
  - `compression` ∈ `none | gz | bz2 | xz | zip`;
  - `zip_members`: chr, for zip only;
  - `encoding` ∈ `UTF-8 | UTF-16LE | UTF-16BE | latin1`;
  - `bom`: lgl;
  - `delim` (chr), `quote`, `decimal` (`.` or `,`), `header` (lgl);
  - `date_order`: named chr, column → `ymd | dmy | mdy | ambiguous`;
  - `quoted_newlines`: lgl;
  - `size_bytes`: dbl;
  - `warnings`: chr.
- Rules:
  - **Format.** Magic bytes win over the extension:
    - `PAR1` → parquet; `ARROW1` → feather; `SQLite format 3\0` → sqlite; `DUCK` at offset 8 → duckdb;
    - `PK\3\4` → zip, unless the `.xlsx` / `.xlsm` extension says xlsx;
    - `\x1f\x8b` → gz; `BZh` → bz2; `\xFD7zXZ` → xz;
    - `$FL2` / `$FL3` → sav;
    - an `<ODM` root element → odm.
  - **Compressed text.** Sniffing continues on the decompressed head:
    - gz via `gzcon(file())`;
    - bz2 via `bzfile`;
    - xz via `xzfile`;
    - zip via `unz` on the single member. With several members, `zip_members` is returned and
      `format = NA` until the caller passes `member`.
  - **Encoding.** A BOM decides first. Otherwise valid UTF-8 (`validUTF8`) → UTF-8, else latin1.
  - **Delimiter.** The candidate among `, ; \t |` with the most consistent non-zero count per line
    over the first 50 lines, outside quotes.
  - **Decimal.** `,` when delim is `;` and numeric-looking fields match `^-?\d+,\d+$`.
  - **Date order.** For columns where ≥ 90% of non-empty values match `\d{1,2}[/.-]\d{1,2}[/.-]\d{2,4}`:
    - `dmy` if some first field > 12;
    - `mdy` if some second field > 12;
    - else `ambiguous`, with a warning naming the column.
  - **Quoted newlines.** TRUE if a quote-balanced scan of the sample finds a newline inside quotes.
- Refusals (errors): a path matching the URL pattern; a path that doesn't exist; a directory.

- [ ] **Step 1: Write `test-sniff.R`.** Each case writes a fixture into a tempdir:
  - comma, semicolon + decimal comma, tab and pipe files give the right `delim` and `decimal`;
  - `.gz`, `.bz2`, `.xz` and a single-member `.zip` of the same CSV give the same `delim` and `header`;
  - a two-member zip returns both `zip_members` and `format` NA;
  - a UTF-16LE BOM file gives `encoding = "UTF-16LE"`;
  - a Latin-1 file whose header is `intToUtf8(c(0xB5,0x6D,0x6F,0x6C))` (written with
    `iconv(..., to = "latin1")`) gives `latin1`;
  - dates `13/02/2020` → `dmy`; `02/13/2020` → `mdy`; only `01/02/2020`-style values →
    `ambiguous`, plus a warning;
  - a quoted field containing `\n` gives `quoted_newlines = TRUE`;
  - parquet and sqlite magic bytes beat a wrong `.csv` extension;
  - `sr_sniff("https://x/y.csv")` errors with `URL`;
  - a missing path errors.

### Task 3: Locked-down DuckDB, fingerprints and the Parquet store

**Files:** Create `app/R/io/duck.R`, `app/R/io/fingerprint.R`, `app/R/io/store.R`, `tests/testthat/test-duck.R`, `tests/testthat/test-store.R`. Modify `app/R/core/lint.R` and `tests/testthat/test-lint.R` (SQL lint).

**Interfaces:**
- Produces:
  - **Connection and SQL.**
    - `sr_duck(project) -> DBIConnection`: in-memory DuckDB with the Global Constraints lockdown,
      `memory_limit = '<caps$duckdb_memory_gb>GB'`, `threads = caps$duckdb_threads`,
      `temp_directory = data/tmp` and `preserve_insertion_order = false`. Caps come from
      `sr_profile_caps(project$meta$profile)`. The result is cached per project dir in a package
      env, and `sr_duck_close(project)` closes it with `shutdown = TRUE`.
    - `sr_duck_exec(con, sql)` and `sr_duck_query(con, sql)`: guarded (Global Constraints), else
      `DBI::dbExecute` / `DBI::dbGetQuery`.
  - **Fingerprints.**
    - `sr_fingerprint(path) -> list(size, mtime, sample_sha)`. `sample_sha` is the SHA-256 of
      three 1 MiB blocks (start, middle, end) read with `readBin` + `seek`.
    - `sr_sha256_file(path, progress = NULL) -> chr`: streams through `openssl::sha256(file(path, "rb"))`.
      When `progress` is set, it reads 8 MiB blocks with an incremental hash and calls
      `progress(done_bytes, total)`.
  - **Store.**
    - `sr_store_dir(project, table)`.
    - `sr_store_write_manifest(project, table, manifest)`: atomic write.
    - `sr_store_manifest(project, table) -> list(table, parts = list(list(file, rows, sha256)), schema = list(list(name, type)), rows)`.
    - `sr_store_hash(manifest) -> chr`: `.sr_sha256(sr_canonical_json(list(schema, parts' sha256 in order)))`.
    - `sr_store_view(project, table)`: creates or replaces the DuckDB view `"<table>"` over
      `read_parquet([parts])`, and returns the table name.
    - `sr_store_tables(project) -> chr`.
    - `sr_table_page(project, table, offset, limit, order_by = NULL) -> data.frame`: server-side
      paging, with `limit` ≤ 1000.
  - **Lint.** `sr_lint_airgap` also flags string constants matching
    `^\s*(FORCE\s+)?(INSTALL|LOAD)\b` (case-insensitive) and calls to `read_json` written inside
    SQL strings.

**Interfaces:**

### Task 5: Delimited-text ingest, chunked and resumable

**Files:** Create `app/R/io/ingest.R`, `app/R/io/read_text.R`, `tests/testthat/test-ingest-text.R`.

**Interfaces:**
- Consumes `sr_sniff`, `sr_duck`, `sr_store_*`, `sr_fingerprint`, `sr_sha256_file` and `sr_preflight`.
- Produces:
  - `sr_ingest(project, path, table = sr_table_name(path), sniff = sr_sniff(path), external = NULL, member = NULL, sheet = NULL, options = list(), chunk_bytes = 256 * 1024^2, progress = NULL, cancel = function() FALSE) -> project`.
    - `external = NULL` means take `preflight$external_suggested`.
    - It runs the pre-flight first and stops with `refuse_reason` if not ok.
    - It dispatches on `sniff$format` to a reader registered with
      `.sr_reader_register(format, fn)`. Task 5 registers `csv`; Tasks 6–7 register the others.
    - On success it appends `data.imported` with payload
      `list(table, format, source = list(path, external, fingerprint, sha256), store = list(dir, rows, ncol, schema, parts), store_hash, resumable, type_widened = chr, sniff = list(delim, encoding, decimal, date_order))`.
    - In non-external mode, the source is first copied into `data/source/<table>.<ext>`. The copy
      computes `sha256` on the way. `source$path` is then relative.
  - `sr_table_name(path, existing = character())`.
  - Reader contract: `function(project, sniff, table, ck, options, progress, cancel) -> list(schema, resumable, type_widened)`.
    - `ck` is the checkpoint object. Readers write parts via `.sr_part_commit(ck, part_file)`, which:
      1. writes the part to `part-NNNNN.parquet.tmp`;
      2. renames it;
      3. records `rows` and `sha256`;
      4. atomically rewrites `data/ingest/<table>/checkpoint.json`;
      5. returns the next part index.
  - `checkpoint.json` contents: `list(source_fingerprint, sniff_hash, chunk_bytes, columns, next_offset, parts, done)`.
    - A resume is accepted only if `source_fingerprint` and `sniff_hash` match; otherwise the
      ingest restarts with a warning.
- **CSV algorithm (`read_text.R`):**
  1. **Decompress first.** If the compression is `bz2`, `xz` or `zip`, stream-decompress (R
     connections, 8 MiB blocks) to `data/ingest/<table>/source.csv`. gz is read by DuckDB directly,
     but **gz is single-pass** (no byte seeks).
  2. **Re-encode.** If the encoding is not UTF-8, stream-convert to UTF-8 the same way (`iconv` per
     block on line boundaries).
  3. **Fix the column types once** from DuckDB
     `DESCRIBE SELECT * FROM read_csv(<file>, delim, quote, decimal_separator, header, sample_size = 1000000)`.
     They are stored in `ck$columns` and passed as `columns = {...}` to every chunk. All
     `date_order != ymd` columns are read as VARCHAR and parsed with
     `strptime(<col>, '%d/%m/%Y')`-style SQL in the same COPY. `ambiguous` columns stay VARCHAR.
  4. **Chunk (only when resumable).** Resumable means: not gz, `quoted_newlines = FALSE`, and the
     file is longer than `chunk_bytes`.
     - Chunk *i* covers the bytes from `next_offset` up to the first `\n` after
       `next_offset + chunk_bytes`.
     - Its bytes are copied (readBin/writeBin, 8 MiB blocks) to `chunk.csv`, with the header line
       prepended.
     - `COPY (SELECT ... FROM read_csv('chunk.csv', columns = ..., header = true)) TO 'part.tmp' (FORMAT parquet, COMPRESSION zstd)`.
     - The chunk file is deleted.
     - `cancel()` and `progress(next_offset, size)` are checked between chunks.
  5. **Otherwise, one COPY** over the whole file (`resumable = FALSE`).
  6. **Type conflict.** On a DuckDB conversion error naming column X:
     - X is set to VARCHAR in `ck$columns`;
     - existing parts are deleted;
     - the ingest restarts from offset 0;
     - X is added to `type_widened`.

     At most `ncol` restarts are allowed.
  7. **Verify.** The total rows in the manifest must equal
     `SELECT count(*) FROM read_csv(<file>, columns = ..., header = true)`. This runs once at the
     end for the single-pass and gz paths; for the chunked path it is the sum of the chunks.

### Task 21: Cohort builder

**Files:** Create `app/R/io/cohort.R`, `tests/testthat/test-cohort.R`.

**Interfaces:**
- Consumes `sr_where_sql` (Task 17), the store and `sr_duck_*`.
- Produces:
  - **Cohort spec.** `sr_cohort_spec(base, id, index = list(table, date_col, where = NULL, pick = "first"|"last"), criteria = list(), features = list(), outcome = NULL, name)`. Components:
    - **Criterion:** `list(label, type = "include"|"exclude", table, where, window = c(lo_days, hi_days) relative to the index date, or NULL)`.
      - An include keeps the ids with ≥ 1 matching row in the window.
      - An exclude drops them.
    - **Feature:** `list(name, table, col, agg ∈ {first,last,count,min,max,mean,any}, window, where)`.

      `event` (0/1).
  - `sr_cohort_sql(project, spec) -> list(steps = chr, final = chr)`.
    - One CTE per step, so each step's distinct-id count can be queried.
    - The final SQL is one row per id: the features and the outcome.

    - Runs the counts for each step and materialises the final table as store table `spec$name`.
    - Appends `cohort.built` with `list(name, spec, sql, flow = data.frame(step, label, n_before, n_after), store_hash)`.
    - The reducer sets `state$cohorts[[name]]` and `state$tables[[name]]` (`format = "cohort"`).
