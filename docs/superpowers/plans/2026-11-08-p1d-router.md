# P1d.2 Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record the research question and the study design, and route them through the pluggable
System One router (rules first, Jev in shadow mode, then the user). Every decision is logged for
replay, frozen by the SAP lock, and used in the Methods and the STROBE checklist.

**Architecture:** One headless layer under `app/R/router/`, plus `app/R/intake/pico.R`.
- **PICO.** `sr_pico_set()` records the research question as free text (`pico.set`). It is the
  user's own words, and it is the main input of the design and purpose nodes.
- **Nodes.** A *node* is one typed decision with fixed options. Examples: the study design, the
  study purpose, which column is the outcome, a covariate's timing.
  - A node is registered with its dependencies, so the graph is a DAG by construction: a node may
    depend only on nodes registered before it.
  - It has an *instance* per scope: the project, a table, or a column. Its key is `design`,
    `outcome_type@t` or `covariate_timing@t:age`.
  - Each instance has an *input hash* over its facts, options and dependency choices. A decision
    whose input hash no longer matches is *stale*. Only stale and pending instances are routed
    again. A current decision is never asked again.
- **Escalation.**
  1. The rule of the node runs first (`backends/rules.R`). A rule that decides acts.
  2. Otherwise each listed model backend is asked in escalation order. In P1 the only one is `jev`,
     in connected mode only. Its prediction is logged (`router.predicted`) together with
     `would_act` from the cost matrix (`abstain.R`), but it **never acts in P1** (shadow mode).
  3. The user decides (`router.decided`, resolver `"user"`), with a reason for any override.
- **Jev.** `backends/jev.R` is the only file that may touch the network.
  - It refuses before any connection unless all of these hold: the mode is connected, a key is set,
    the project has a DPA / IT acknowledgement, the R session has consent, and the exact payload
    hash was approved after a preview.
  - Every event is already chained into `audit.log` (`event:<type>` with its payload SHA), so the
    decision record is tamper-evident without new audit code.
- **Lock and writer.**
  - The SAP check blocks while the design or the purpose is undecided or stale, and when a primary
    causal analysis adjusts for a mediator or a post-outcome column.
  - The decisions and the PICO join the SAP hash.
  - The writer adds a "Study design" Methods paragraph and a decision table to the supplement.
    STROBE items 3-5 turn green.

**Tech Stack:** R 4.5.2; `curl` (installed) for the one HTTP call, loaded only inside `jev.R`;
`openssl` for the session id; testthat 3e. **No new packages.**

## Review Focus
1. **Data or the key leaks into a payload or the log.**
   - Examples: a factor level or free-text cell value in the state; a row count of 3; the Jev key in
     an event, the audit log or an error; a payload sent that differs from the one previewed.
   - Expected:
     - the state carries names, labels, types, roles and bucketed counts only;
     - a person count of 1-4 prints `"<5"`;
     - the sentinel key is found in no file under the project;
     - a request whose payload SHA is not in `approve` is never sent: no transport call, logged as
       `error = "payload not approved"`.
   - Pinned: Task 4 (state) and Task 7 (key, approval).
2. **The network in air-gap mode, or a failing Jev.**
   - Cases: air-gap mode with `backends = "jev"`; a timeout; HTTP 400, 422 and 500; a non-JSON body;
     a choice outside the criteria; probabilities that do not sum to 1.
   - Expected:
     - in air-gap mode the fake transport is called 0 times;
     - every failure is one `router.predicted` with `error` set and `choice = NA`;
     - the instance stays `pending` for the user, the run carries on with the next instance, and
       nothing is retried.
   - Pinned: Task 2 (parse) and Task 7.
3. **Reopen, and upstream changes.**
   - Cases: the project is closed and reopened, then `sr_router_run` is called again; the PICO is
     edited; roles are re-confirmed with a different outcome.
   - Expected:
     - on reopen, nothing is asked again (0 transport calls; no new `router.decided`);
     - after a PICO edit, `design` and `purpose` (and everything that depends on them) become
       `stale`, and nothing else does;
     - a stale `design` blocks the lock until it is decided again.
   - Pinned: Task 5 (engine) and Task 9 (gate).
4. **Awkward column sets.**
   - Cases: 300 columns (above the 255-criteria limit with `"none"`); names with quotes, colons,
     spaces or non-ASCII characters; two columns with the same label; a table with no covariate; a
     describe study (no exposure).
   - Expected:
     - with too many columns, no model is asked for the column nodes (rule or user only), and the
       state stays within `SR_ROUTER_MAX_TOKENS`;
     - criteria keys are always `c001`... and never the raw names;
     - `exposure_col` and `covariate_timing` do not apply to a describe study.
   - Pinned: Task 4 and Task 6.
5. **Overrides and vetoes.**
   - Cases: a choice outside the node's options; a vetoed choice; a fourth veto on one key; an
     override with no reason; the user picking something other than the rule's choice.
   - Expected:
     - an unknown option is an error listing the options;
     - a veto is refused with its reason and logged (`router.vetoed`);
     - after `SR_ROUTER_MAX_VETOES` vetoes, the table status is `override_required`;
     - `override = TRUE` with an empty reason is an error;
     - an override is stored with `override = TRUE` and `suggested`, and appears in the supplement's
       decision table.
   - Pinned: Task 5, Task 6 and Task 10.

Further cases a reviewer should probe, each pinned in its task:
- **A user-text PICO holding digits or markup** ("adults aged 18-65", "2010 to 2020", "<5 y", `&`).
  It reaches the docx only through `{{L}}` tokens, so the guard passes and the characters stay
  unchanged (Task 10).
- **The SAP hash of a project with no router events** equals the pre-P1d.2 value (Task 9).

### Task 2: System One protocol and the cost-matrix abstain rule

**Files:**
- Create: `app/R/router/sysone.R`, `app/R/router/abstain.R`, `tests/testthat/test-router-sysone.R`
- Modify: `app/global.R`

**Interfaces:**
- Produces (`sysone.R`):
  - **`sr_sysone_choice(instructions, criteria) -> list(type = "choice", instructions,
    criteria)`**.
    - `criteria` is a named list of option key to description (`character(1)` or NULL).
    - It errors when there are 0 or more than `SR_SYSONE_MAX_CRITERIA` entries, when a key is
      duplicated or empty, or when the instructions are empty.
  - **`sr_sysone_request(state, questions, model = sr_opt("jev_model", "jev-latest")) ->
    list(model, state, questions)`**. `state` is `character(1)`; `questions` is a named list of
    `sr_sysone_choice`.
  - **`sr_sysone_body(request) -> chr`**: `sr_canonical_json(request)`, the exact bytes sent.
  - **`sr_sysone_sha(request) -> chr`**: `.sr_sha256(sr_sysone_body(request))`.
  - **`sr_sysone_confidence(p) -> num`** = `(max(p) - 1/n) / (1 - 1/n)`, where `n = length(p)`.
    It is 1 when n is 1.
  - **`sr_sysone_parse(response, request) -> named list`**, one element per question:
    `list(ok, choice, probabilities, confidence, error)`.
    - `response` is the parsed body (a list).
    - `ok = FALSE`, with an `error` message, when: the answer is missing; the type is not
      `"choice"`; the choice is not one of the criteria keys; the probabilities' names are not a
      subset of the keys; any probability is outside [0, 1]; or the probabilities do not sum to 1
      within 1e-3.
    - Missing keys get probability 0.
    - The confidence is always recomputed with `sr_sysone_confidence` over all criteria, never
      copied from the response.
  - **The backend registry:**
    - `sr_backend_register(id, ask, available)`:
      - `ask(request, ctx) -> list(ok, response, raw, model, latency_ms, error)`;
      - `available(project) -> list(ok, reason)`.
    - `sr_backends() -> chr` gives the registered ids.
    - `.sr_backend_get(id)` errors on an unknown id.
- Produces (`abstain.R`):
  - **`sr_cost_matrix(options, danger = list()) -> matrix`**:
    - rows are the true option, columns the chosen one;
    - 0 on the diagonal, 1 elsewhere;
    - each `danger` element `c(true, chosen)` sets that cell to `SR_ROUTER_DANGER_COST`;
    - an unknown option in `danger` is an error.
  - **`sr_abstain(probabilities, cost, ask_cost = SR_ROUTER_ASK_COST) -> list(act, choice,
    expected_cost)`**:
    - `expected_cost[a] = sum_j p[j] * cost[j, a]`;
    - `choice` is the argmin, ties going to the first option in `colnames(cost)` order;
    - `act` is `expected_cost[choice] < ask_cost`.

- [ ] **Step 1: Write the failing tests** in `test-router-sysone.R`:
  - `"sr_sysone_choice enforces the criteria limits"`:
    - 256 criteria error with `"255"`;
    - 0 criteria error;
    - duplicated keys error;
    - 255 criteria pass.
  - `"the request body is canonical and its sha is stable"`: two requests built with the questions
    in a different list order have the same `sr_sysone_sha`.
  - `"sr_sysone_confidence follows the TypeSafe formula"`:
    - `c(a = 0.7, b = 0.2, c = 0.1)` gives `(0.7 - 1/3) / (2/3)`;
    - a uniform `p` gives 0;
    - `c(a = 1)` gives 1.
  - `"sr_sysone_parse accepts a well-formed answer"`:
    - response `list(answers = list(design = list(type = "choice", choice = "case_control",
      probabilities = list(case_control = 0.8, cohort_retrospective = 0.2))))` gives ok, that
      choice, 0 for the missing keys, and the recomputed confidence;
    - a `confidence = 0.99` field in the response is ignored.
  - `"sr_sysone_parse rejects malformed answers"`, one case each, all `ok = FALSE` with a non-empty
    `error`: a choice not in the criteria; probabilities summing to 1.2; a negative probability; a
    missing answer; type `"score"`.
  - `"sr_abstain acts only below the ask cost"`:
    - with the uniform cost matrix, `p = c(a = 0.95, b = 0.05)` gives act TRUE and choice `"a"`;
    - `c(a = 0.85, b = 0.15)` gives act FALSE.
  - `"a dangerous cell moves the choice"`:
    - with `danger = list(c("b", "a"))` and `p = c(a = 0.6, b = 0.4)`;
    - `expected_cost` is `c(a = 4, b = 0.6)`, so the choice is `"b"` and act is FALSE.
  - `"the backend registry"`:
    - registering a test backend `"fake"` makes it appear in `sr_backends()`;
    - `.sr_backend_get("nope")` errors with `"unknown backend"`;
    - remove the test backend with `withr::defer`.

### Task 5: Rules backend and the routing engine

**Files:**
- Create: `app/R/router/backends/rules.R`, `app/R/router/engine.R`, `tests/testthat/test-router-engine.R`
- Modify: `app/global.R`, `tests/testthat/helper-router.R`, `app/R/router/graph.R` (stale-aware

**Interfaces:**
- Consumes: Tasks 2-4.
- Produces:
  - **The reducers** for `router.predicted`, `router.decided`, `router.vetoed`, `router.consent` and
    `router.jev_ack` (shapes in Global Constraints). The consent and ack *calls* are Task 7.
  - **`.sr_router_rule(ctx) -> list(choice, reason) | NULL`** (`rules.R`):
    - it runs `node$rule(ctx)`;
    - a choice outside `options(ctx)` is an error naming the node, because a bad rule is a code bug.
  - **`sr_router_run(project, backends = character(), approve = character()) -> project`**: for
    each instance of `.sr_router_instances` in order, skipping any with an NA dependency or with
    `applies` FALSE:
    - a current decision (same input hash) is skipped;
    - if `.sr_router_rule` gives a choice, it appends `router.decided` with resolver `"rules"`,
      `override = FALSE` and `reason` set to the rule's reason;
    - otherwise, if `sr_router_request` is not NULL, it walks `intersect(SR_ROUTER_ESCALATION,
      backends)`:
      - a backend that is unregistered or not `available(project)$ok` is skipped silently;
      - a backend that already has a *successful* prediction (`error` NA) with the same
        `input_hash` is not asked again (replay). A failed prediction is not replayed, so a later
        run (for example, after the payload is approved) asks again; within one run nothing is
        retried;
      - otherwise it calls `ask(request, ctx)` and appends one `router.predicted` with
        `would_act = sr_abstain(...)$act` (FALSE on error);
      - it stops at the first prediction with `would_act` TRUE;
    - the instance is then left `pending`.

    `approve` is passed to the backends in `ctx$approve`. The ctx is rebuilt after every append,
    so a later instance sees a rule decision made earlier in the same run.
  - **`sr_router_decide(project, node, choice, reason = NA_character_, table = NA_character_,
    column = NA_character_, override = FALSE) -> project`**:
    - it refuses after the lock with `.sr_sap_open(project, "the SAP is locked: router decisions
      are frozen")`;
    - it errors when the instance does not exist or does not apply, or when a dependency is
      undecided;
    - it errors when `choice` is not in `options(ctx)`, listing them;
    - if `node$veto(ctx, choice)` gives a reason and `override` is FALSE, it appends
      `router.vetoed` and then errors with that reason;
    - `override = TRUE` needs a non-empty reason;
    - `suggested` is the rule's choice, else the latest prediction's choice, else NA;
    - when `suggested` is not NA and differs from `choice`, the decision is stored with
      `override = TRUE`, and a reason is then required (an error says so);
    - it appends `router.decided` with resolver `"user"`.
  - **`sr_router_choice(project, node, table = NA, column = NA) -> chr`** gives the current choice,
    or NA when undecided or stale.
  - **`sr_router_table(project) -> data.frame`** with columns key, node, label, table, column,
    status, choice, resolver, override, reason, suggested, backend, model_choice, confidence,
    would_act and vetoes.
    - `status` is one of:
      - `"decided"`;
      - `"stale"` (decided, input hash changed);
      - `"pending"` (applies, no current decision);
      - `"waiting"` (a dependency undecided);
      - `"override_required"` (pending, with vetoes >= `SR_ROUTER_MAX_VETOES`).
    - Instances that do not apply are left out.
    - This is the expert decision table.

    - It restores the real backend on exit (save `.sr_backend_get("jev")` first, if Task 7 has
      registered it).

### Task 7: The Jev backend (connected mode only)

**Files:**

- Produces:
  - **`sr_router_session() -> chr`**:
    - 16 hex characters from `openssl::rand_bytes(8)`;
    - created once per R process and cached in `.sr_router_env`;
    - never touches `.Random.seed`.
  - **`sr_router_consent(project, granted = TRUE) -> project`** appends `router.consent`
    {session = sr_router_session(), granted}.
  - **`sr_router_jev_ack(project, reason) -> project`** appends `router.jev_ack`. It records that
    the DPA / PDPA and institutional IT sign-off are documented, and the reason (non-empty) cites
    them. It is refused while read-only.
  - **The backend `"jev"`**, registered at source time:
    - **`available(project)`** gives `ok = FALSE`, with one `reason`, for each failing gate, checked
      in this order:
      1. `sr_mode() != "connected"`: "air-gap mode";
      2. `!nzchar(sr_opt("jev_key", ""))`: "no Jev key (set SR_JEV_KEY)";
      3. no `state$router$jev_ack`: "no DPA / IT acknowledgement for this project";
      4. `!isTRUE(state$router$consent[[sr_router_session()]])`: "no consent in this session".
    - **`ask(request, ctx)`**:
      - it re-checks `available` first;
      - if `sr_sysone_sha(request)` is not in `ctx$approve`, it gives `ok = FALSE, error = "payload
        not approved"` **without calling the transport**;
      - otherwise it POSTs `sr_sysone_body(request)` to `sr_opt("jev_url", ...)` with the headers
        `Authorization: Bearer <key>` and `Content-Type: application/json`, and a timeout of
        `as.numeric(sr_opt("jev_timeout", 20))` seconds;
      - the transport is `sr_opt("jev_transport", NULL) %||% .sr_jev_curl`;
      - `latency_ms` is measured around the transport;
      - it never retries.
    - **Errors.** Each of these maps to `ok = FALSE` and an `error`, with the key never included:
      - a transport error (a timeout included): its message, with the key `gsub`-ed out;
      - status 400: `"HTTP 400: <detail>"`;
