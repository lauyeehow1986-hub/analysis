# CLAUDE.md — StatRouter

## What this is
A **portable, air-gap-capable R Shiny application for healthcare data analysis**.

- **Routing.** A pluggable **System One router** makes each analysis decision. It tries deterministic
  rules first, then a typed-judgment model (TypeSafe **Jev** in the cloud; **Von 1.3** or **CLM-8B**
  locally), then asks the user.
- **Pipeline.** Raw file → profiled and cleaned → SAP-locked, pre-specified, assumption-checked
  analysis → **manuscript-ready Word output**: Methods, Results, tables, figures, reporting checklist,
  and the exact `analysis.R` that ran.
- **Archive.** Projects are archived so they can be reopened to **answer peer reviewers**.
- **Risk calculators.** The app builds a single-file offline HTML calculator plus a developer handover
  package.

This is a research and governance tool, **not for clinical or diagnostic use**. Outputs need review
by a qualified statistician. **Never commit real patient data** — only synthetic samples generated by
`samples/*.R`.

The design is the source of truth: [docs/specs/2026-10-03-statrouter-design.md](docs/specs/2026-10-03-statrouter-design.md).
Running state, decisions and gotchas live in [memory.md](memory.md). Update it when a phase ends, a
decision changes, or a gotcha is found.

## Non-negotiable rules
- **Models route; they never compute or write numbers.** Every number comes from evaluated R code.
  Prose uses locked placeholders (`{{E1}}`), checked by the claim guard.
- **No test-gated method switching.**
  - Defaults are robust by design.
  - A failed diagnostic *adds a sensitivity node*. It changes the primary analysis only through a
    rule written into the locked SAP.
  - A lint test fails the build if a route's `compile()` branches on a diagnostic p-value.
- **Every route declares an estimand and a `purpose`** (describe / predict / explain-causal), or it
  fails registration.
- **Air-gap mode makes no network calls, ever.**
  - Never call `reticulate::py_available(initialize=TRUE)` or anything else that triggers uv/pip
    provisioning. This includes the CRAN `tabpfn` package's uv auto-install, which must be disabled.
  - Bundled Python is detected passively, by checking for the interpreter on disk.
  - Model weights are pre-staged and SHA-pinned.
- **Licence gates are the user's decision.**
  - Non-commercial weights (TabPFN 2.5–3.5, LimiX) are acknowledged once per project, logged, and
    cited in the Methods.
  - SMOTE-type resampling is the user's choice. It is applied within each fold, and the model is
    recalibrated (intercept and slope) within the same fold.
- **Risk calculators export only the spec**, never R model objects.
  - Instance-based models (kNN, RBF-SVM, GP, LOESS, TabPFN) are hard-blocked.
  - Export requires four-way equivalence: the fitted object, the R spec evaluator, the Python spec
    evaluator, and the HTML's own JS run headless.
- **Code-first execution.** A route's `compile(spec)` returns an R code string. That string is what
  runs and what gets exported.
- **Event-sourced projects.** `events.jsonl` is authoritative; Shiny state never is.

## Tech stack
- **Core:** R 4.5.x, Shiny, bslib; officer/flextable for docx (no pandoc); mirai + callr; processx;
  DuckDB → Parquet for large data (up to 100 GB).
- **Analysis packages:** tidymodels and mlr3; rstanarm (precompiled Stan; brms on the laptop profile
  only); lavaan.
- **Bundled Python:** runs the local System One models (ONNX/OpenVINO, llama.cpp) and the Python
  learners over stdio JSON-lines.
- **Hardware profiles:** `locked16` (CPU-only, 16 GB) and `laptop` (i7-13650HX, 24 GB, RTX 4060 8 GB).
  The profile caps workers, RAM use and model tier.

## Conventions
- Language is R. Exported core functions use the **`sr_` prefix** (`.sr_` for internal ones), in
  `snake_case`.
- One concern per file. The core is pure and testable without the UI; use `testServer` for reactive
  logic.
- Read options with `getOption("sr.x", Sys.getenv("SR_X", default))`.
- Generated `.ps1` and `.R` scripts are **ASCII only**.

## Build & run (dev)
- `& "C:\Program Files\R\R-4.5.2\bin\Rscript.exe" -e "shiny::runApp('app', port=7790)"`
- Tests: `Rscript -e "testthat::test_dir('tests/testthat')"`
- Never run long multi-line code through `Rscript -e`; it segfaults on this machine. Use a script
  file.
